## Problem Statement

In Plane mode the Board is always `/workspaces/{slug}/…`. Today the slug is only argv `--workspace`, env `PLANE_WORKSPACE`, or default `personal`. A user can already type `--workspace` into **Scope flags** and Refresh, but there is no dedicated control, and a Jira Board must not grow a Plane Workspace switcher. Google SSO is not Workspace selection.

## Solution

In **Plane mode only**, put a header **Workspace** pill beside the project-identifier chip. The user types a slug, Enter writes `--workspace <slug>` into Scope flags (always, including `personal`), and the existing Refresh confirm runs **all Epics** for that Workspace. Jira omits the pill. Next launch still uses argv > env > `personal`. Typed slug, not a list API (ADR-0015).

6. As a Plane Board user, I want the pill beside the project-identifier chip, so that Workspace and Project stay distinct.
7. As a Plane Board user, I want to click the pill and type a slug, so that I can name the target Workspace.
8. As a Plane Board user, I want Enter to commit the typed slug, so that I explicitly switch.
9. As a Plane Board user, I want blur without Enter to discard the draft, so that an accidental click-away does not open Refresh.
10. As a Plane Board user, I want an empty slug rejected and the previous value kept, so that I cannot Refresh with a blank tenant.
11. As a Plane Board user, I want typing the same live slug to be a no-op, so that I do not get a Refresh dialog for no change.
12. As a Plane Board user, I want leading and trailing whitespace trimmed, so that `" team "` is the same slug as `team`.
13. As a Plane Board user, I want slug case kept as typed, so that we do not invent Plane's slug grammar.
14. As a Plane Board user, I want commit to replace or insert a single `--workspace <slug>` in Scope flags, so that two `--workspace` tokens cannot drift.
15. As a Plane Board user, I want `--plane` and `--projects` left untouched, so that Workspace switch is not a Project picker.
16. As a Plane Board user, I want `--workspace personal` written even when that is the default, so that an env `PLANE_WORKSPACE` cannot bounce the pill back.
17. As a Plane Board user, I want commit to open the existing Refresh confirm, so that ADR-0013 still gates Board replace.
18. As a Plane Board user, I want that confirm to Refresh **all** Epics, so that the new Workspace catalog actually loads.
19. As a Plane Board user, I want Refresh selected visible and disabled on that confirm, so that a focused Epic from the old Workspace cannot be the switch path.
20. As a Plane Board user, I want the dialog copy to name the target Workspace slug, so that I know which tenant will be listed.
21. As a Plane Board user, I want Cancel to restore Scope flags and the pill to the last successful slug, so that Cancel means do not switch.
22. As a Plane Board user whose last successful slug came only from env (no `--workspace` in flags), I want Cancel to restore that original flags string, so that Cancel does not invent a flag I never committed.
23. As a Plane Board user, I want header Refresh and Command Refresh to keep the normal all-or-selected dialog, so that only the pill's confirm forces all.
24. As a Plane Board user, I want a failed Refresh (unknown slug, 404, 403) to keep the attempted flags and pill, so that Retry is the same switch.
25. As a Plane Board user, I want a failed Refresh to keep the previous Board, so that a bad slug does not wipe Cards.
26. As a Plane Board user, I want the existing Plane error toast (`Plane {status}: …`), so that this job does not invent a second error surface.
27. As a Plane Board user, I want Favourites reset after a **successful** all-Refresh whose resolved Workspace differs from the stamp on the Favourite blob, so that leftover Epic keys from another tenant do not linger.
28. As a Plane Board user, I want Filter, Sort, Hide, and Presets to stay last-used after a Workspace switch, so that chrome is not keyed by tenant in this job.
29. As a Plane Board user, I want Cancel and failed Refresh to leave stored Favourites alone, so that a switch I did not land does not wipe stars.
30. As a Plane Board user, I want argv `--workspace`, env `PLANE_WORKSPACE`, and default `personal` unchanged on next launch, so that the in-app switch is session-only.
31. As a Plane Board user, I want to keep typing `--workspace` in Scope flags, so that the dedicated pill is an addition, not a removal.
32. As a tester, I want `GET /api/board` to include process `kind`, so that the client does not infer Plane from `--plane` in flags.
33. As a tester, I want Plane board JSON to include the resolved `workspace` slug (`--workspace` else env else `personal`), so that the pill can show env default without rewriting flags.
34. As a tester, I want Jira and store board JSON to omit `workspace`, so that a Jira process never claims a Plane slug.
35. As a tester, I want Refresh JSON to carry the same `kind` and resolved `workspace` envelope, so that a successful switch updates the pill from the response.
36. As a tester, I want Refresh-all with `--workspace other` to list `/workspaces/other/…`, so that Scope flags are the source of truth for the live slug.
37. As a Plane Board user, I do not want a list-workspaces dropdown, so that we do not ship against an unmerged PAT route.
38. As a Plane Board user, I do not want Google SSO to pick Workspace, so that login stays orthogonal to tenant slug.
39. As a maker, I want glossary **Workspace** and ADR-0015 on the feature branch, so that the typed-slug decision is in git.

## Implementation Decisions

- **Primary seam:** the Board JSON the chrome already loads, plus the Scope flags string Refresh already POSTs. No `/api/workspace`. No list-workspaces. No second slug store.
- **Envelope:** `GET /api/board` and Refresh responses include `kind` (`plane` | `jira` | `store`). When `kind === "plane"`, also `workspace` (resolved: flags `--workspace`, else `PLANE_WORKSPACE`, else `personal`). Other kinds omit `workspace`. Existing board tests stay valid with an extra `kind` field (store/jira listeners default `kind` to `store` unless the test boots Plane).
- **Kind source:** process boot kind, threaded into the HTTP handler. Not `wantsPlane(Scope flags)`.
- **Flags rewrite:** a pure helper beside `parseFlags` that replaces an existing `--workspace` / `--workspace=` token or inserts `--workspace <slug>`. Always writes the token on commit, including `personal`. Trims the slug. Leaves `--plane`, `--projects`, and remaining tokens. Empty slug is not a rewrite (caller rejects).
- **Pill display:** Plane only, header, beside the project-identifier chip. Shows resolved live slug. Click to edit. Enter commits; blur discards. Same resolved slug → no rewrite, no dialog. Accessible name **Workspace** (not Project).
- **Commit path:** rewrite Scope flags in the input, then open the existing Refresh AlertDialog with those flags pending. That confirm always uses Refresh **all**. Refresh selected stays visible and disabled. Title stays **Refresh**. Description names the target Workspace slug. Primary remains **Refresh all Epics**.
- **Cancel:** restore the flags string from before this pill commit, and show the last successful resolved slug. Do not POST.
- **Last successful slug:** session value from initial board load and from each **successful** all-Refresh. Failed Refresh does not update it. Cancel uses it for the pill; flags revert to the pre-commit string.
- **Failure:** keep attempted flags and pill; previous Board stays; existing error toast. Server already assigns flags before the list call; do not add a revert-on-error path.
- **Favourites:** stamp the resolved Workspace on the Favourite blob the same way `--projects` is already stamped. After **successful** all-Refresh, if the new resolved Workspace does not match the stamp, reset keys/folders and stamp the new slug. Do not reset on pill-write, Cancel, or failed Refresh. Filter / Sort / Hide / Presets unchanged. Do not key last-used chrome by Workspace.
- **Plane CLI:** catalog and REST continue to use `planeWorkspace(flags)` on Refresh. Tests must not hardcode only `personal` if they claim a slug switch.
- **Docs on the feature branch:** CONTEXT.md **Workspace** (and Project Avoid), ADR-0015 typed slug. README may mention the pill; argv/env table stays.
- **Git:** `feat:` on `feat/plane-workspace-switcher` from `origin/main`. Do not merge PR #58. Do not invent tenant slugs in commits. Do not bump package.json or run semantic-release.
- **No React test runner.** ui-review is the extra-checker after Referee.

## Testing Decisions

- Test external behaviour: flags string in/out, board/refresh JSON envelope, Plane REST path slug, Refresh-all vs selected body. Do not assert component internals.
- **Flags tests** (existing suite): rewrite/insert `--workspace`; keep `--plane` and `--projects`; trim; `personal` still written; `--workspace=` replaced.
- **HTTP tests** (existing listen helper): Plane `kind` + resolved `workspace` from flags, from env when flags omit it, and `personal` when both omit; Jira/store omit `workspace`; Refresh-all response envelope matches.
- **Plane CLI tests** (existing fake fetch): Refresh/list with `--workspace other` calls `/workspaces/other/…` (fake must not match only `personal`).
- **Refresh body tests:** Workspace confirm uses `scope: "all"`; do not add a second refresh route.
- Favourites reset is session chrome; extract a small pure stamp/compare helper if a unit test is needed. Do not add a persistence module.
- Prior art: flags `--workspace` parse; planeWorkspace precedence and fake REST; `/api/board` and `/api/refresh`; refresh all vs selected.
- No RTL / Playwright in this job. ui-review covers pill omit-on-Jira, Enter vs blur, disabled selected, dialog copy.

## Out of Scope

- List-workspaces / probe `GET /api/v1/users/me/workspaces/` (ADR-0015).
- Last-used Workspace in localStorage; argv/env/default still win on next launch.
- Workspace switcher in Jira; disabled Jira control (omit entirely).
- Google SSO / oauth2-proxy as Workspace selection (`gbj-20260918-002`).
- Command overlay row for Workspace.
- Changing `--projects` on switch; a second Project picker.
- Keying Filter / Sort / Hide / Presets by Workspace.
- Silent Refresh; a second HTTP refresh path.
- PR #58 (`fix/plane-429-keep-mode`) and 429 retry behaviour.
- Inventing a version number; package.json bump; semantic-release.

## Further Notes

- Glossary: **Workspace** is the Plane tenant slug. **Project** is `--projects` identifiers. Do not call the pill Project.
- Locked ask: Plane mode only, where a Workspace exists.
- VERSION-IMPACT minor → conventional-commits `feat:`.
- Generic example slugs in tests: `personal`, `team`, `other`. No real tenant names in git.
