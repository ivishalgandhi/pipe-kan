## What to build

Favourite is a local pin of an Epic, not Scope, Filter, or Hide. A star on every Epic row (Favourites group and status groups) toggles membership. Starring does not select the Epic. Clicking the rest of the row still shows only that Epic's children. A Favourite also stays in its status group.

Favourites sit in a collapsible group between All stories and the Epics heading. Hidden when empty. Default open; collapse persists like the other Epic status groups. Order: Epic priority using the same rank as Card Sort (P1 / Highest / Critical, then P2 / High, then P3 / Medium, then lower, then missing); ties and missing priority by Issue key A–Z. Persist Favourite keys in their own store so clearing Filter cannot wipe them. A key that Refresh drops stays stored and reappears when that Epic is listed again. Search omits a Favourite row that does not match.

## Acceptance criteria

- [ ] A star on every Epic row toggles Favourite. Star does not select. The rest of the row still shows that Epic's children.
- [ ] A Favourited Epic remains in its status group as well as in Favourites.
- [ ] The Favourites group sits between All stories and the Epics heading. It is hidden when no visible Favourite remains. Default open; collapse persists like other Epic groups.
- [ ] Favourites are ordered by Epic priority (shared rank with Card Sort). Ties and missing priority by Issue key A–Z.
- [ ] Favourite keys persist separately from the Filter / Sort / Hide blob. Clearing Filter does not wipe them. Starring is not `-P` and does not change Scope.
- [ ] A Favourited key missing after Refresh stays stored and is painted again when that Epic is in the list.
- [ ] Header Search omits a Favourite row that does not match (same rule as the rest of the pane). The star stays; the row returns when Search clears.
- [ ] Tests sit next to Epic grouping tests: priority order, empty group hidden, Search omits a non-matching Favourite, stale keys do not invent rows. Star chrome is not tested.
