## What to build

Clicking a Card Opens the side pane immediately with that Card plus the Jira URL. Then `jira issue view KEY --raw` fills description and every other non-empty field. `jira open KEY` still resolves the URL. Remote Jira refuses frames: fields plus the link. Same-origin Fake Jira: the same fields, and the iframe under them.

Field order: key, summary, Jira URL, priority, assignee, due date, labels as capsules, description (extracted text, not HTML), then every other non-empty field A–Z. Skip comments, changelog, empty values, and raw schema dumps. Custom field label: a nested `.name` on the value when present, otherwise the field key. No `jira fields` catalog. If view fails, keep Card fields and the link and show the error in the pane. The pane stays open if Filter or Hide later removes that Card.

## Acceptance criteria

- [ ] Clicking a Card Opens the pane immediately with key, summary, and the Jira URL (and any other fields already on the Card).
- [ ] A successful `jira issue view KEY --raw` fills description and other non-empty fields without a second click.
- [ ] If view fails, the pane keeps Card fields and the link and shows the error. It does not go blank.
- [ ] Field order is key, summary, URL, priority, assignee, due, label capsules, description, then remaining non-empty fields A–Z.
- [ ] Description is extracted text (ADF or wiki flattened). Not HTML.
- [ ] Comments, changelog, empty values, and schema dumps are omitted.
- [ ] Custom fields use a nested `.name` when the value has one; otherwise the field key (including `customfield_*`).
- [ ] Remote Jira: fields plus a link. No dead iframe. Fake Jira / same-origin: fields plus the iframe under them.
- [ ] Closing the pane is explicit. Filter or Hide removing that Card does not close it.
- [ ] Open's HTTP body is URL plus flattened fields. Fake view returns the stored Issue. Tests follow the existing Open URL tests; iframe layout is not tested.
