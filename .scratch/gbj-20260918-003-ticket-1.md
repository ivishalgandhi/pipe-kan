## What to build

The Board JSON the chrome already loads must tell the client it is Plane, and which Workspace slug is live, without a new HTTP route. Scope flags must be able to name that slug with a single `--workspace` token so Refresh-all lists `/workspaces/{slug}/…`. Glossary **Workspace** and ADR-0015 (typed slug, not a list API) land on `feat/plane-workspace-switcher`. No pill yet.

## Acceptance criteria

- [ ] `GET /api/board` includes process `kind` (`plane` | `jira` | `store`). Kind is boot kind, not `--plane` in Scope flags.
- [ ] When `kind === "plane"`, the same payload includes resolved `workspace`: flags `--workspace`, else `PLANE_WORKSPACE`, else `personal`.
- [ ] Jira and store payloads omit `workspace`.
- [ ] Refresh (all) JSON carries the same `kind` / `workspace` envelope after flags change.
- [ ] A helper replaces or inserts one `--workspace <slug>` in a flags string. Always writes the token, including `personal`. Trims. Leaves `--plane` and `--projects`. Does not invent a second token.
- [ ] Plane CLI Refresh-all with `--workspace other` lists `/workspaces/other/…` (fake must not match only `personal`).
- [ ] Tests in the existing flags, HTTP, and Plane CLI suites. No `/api/workspace`. No list-workspaces. No React tests.
- [ ] `CONTEXT.md` **Workspace** (Project is not that slug) and ADR-0015 are on the feature branch. Generic slugs only (`personal`, `team`, `other`).
- [ ] `feat:` on `feat/plane-workspace-switcher` from `origin/main`. Do not merge PR #58. Do not bump package.json or run semantic-release.
