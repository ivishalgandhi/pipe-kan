## Parent

#49 — Calendar events show Issue key and summary

## What to build

On Calendar, each event is readable at a glance: the chip (and the `+more` popover) shows the Issue **key** and **summary**, not the key alone. A long summary truncates to one line in the day cell; native hover shows the full string plus whether the day is created or Target End. Click still Opens the same Issue pane.

Mapping owns both strings from the Card:

- **Chip / FullCalendar title:** `KEY` then a space then the trimmed summary. After trim, empty summary → key only (no trailing space). Same for Epic and non-Epic Cards. Kind is not on the chip.
- **Native hover:** `{chip} · created` or `{chip} · target end` (blank summary: `KEY · created` / `KEY · target end`).

The Calendar UI paints those two strings (stop painting key only) and keeps one-line ellipsis with nowrap. Created vs Target End colors/classes, dates, ids, Open-by-key, tabs, and which Cards appear stay as shipped.

Commit as conventional-commits `feat:`. Do not invent a version number, do not bump the package manifest, do not run semantic-release.

## Acceptance criteria

- [ ] Given a Card with a summary, Calendar mapping `title` is `KEY` + space + trimmed summary (example: `DEMO-2 Parse JSON`), for both the created event and the Target End event.
- [ ] Given a Card whose summary is missing or only whitespace, mapping `title` is the key alone (no trailing space).
- [ ] Mapping native-hover string is `{title} · created` or `{title} · target end` using those kind words.
- [ ] Epic Cards and non-Epic Cards use the same title and hover rules.
- [ ] Calendar UI chip text is that `title` (not the key alone); native `title=` is the mapping hover string.
- [ ] Day-cell chip stays one line with ellipsis (nowrap on the existing chip class). No tooltip library.
- [ ] Click still Opens via the Issue key. Event ids, start days, class names, and which Cards feed Calendar are unchanged.
- [ ] Due date and Target Start still do not create events. Cards with no created day and no Target End still paint none.
- [ ] Existing mapping tests that expected `KEY created` / `KEY target end` as `title` are updated; Open-key helper tests still pass.
