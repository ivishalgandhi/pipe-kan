# Epic children cache is for the pane, not the Board

Refresh lists every Epic (`-tEpic`) and, in one extra jira-cli call, every non-Epic child of those keys. The left-pane count and Filter/Search hide-row use that cache. The Board still shows only Scope. Fixture and the store adapter fill the cache from the in-process store at hydrate so first paint matches Refresh; a Pipe stays Scope-only until Refresh. If the children call fails, the Board stays and counts fall back to Scope Cards. Merging those children into Columns would leak Scope; fetching per Epic on click leaves the number wrong until select. jira-cli `--raw` drops Epic Link; when the batched list has children but no Epic keys, Refresh skips the cache (counts fall back to Scope) instead of listing each Epic. Select still lists that Epic's children when the cache has none for that key. Refresh replaces Scope, listed Epics, and the cache together so first paint never pairs new Epics with the last children.
